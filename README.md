# Shield Turbo · xiaonuo（疾风铁盾 · 性能压榨与安全加固基准）

> **一句话**：给大模型一套由 **16 个跨模块交织文件**组成的“业务逻辑 100% 正确、功能冒烟全绿，但既慢（暗藏多级算法复杂度、跨文档引用放大与高频混写抖动黑洞）又脆（暗藏双通道跨模块二阶注入、模板反射/宽度放大、跨租户状态侧信道、二级委托环路、跨接口配额交叉死锁与半批泄漏）”的多租户实时风控与合规检索网关——看谁能在**正常业务与跨模块兼容契约分毫不差**的前提下，同时顶住**高频混写压测机**与**二十路深水红队轰炸机**的双重考验。

当前赛制版本为 `xiaonuo-v3.0`（十六模块跨链路耦合深水版）；纯 Python 标准库 + 本地 SQLite 零外部依赖同仓闭环运行。最新成绩见 [`leaderboard/scores.md`](leaderboard/scores.md)，智能体进场操作请直接阅读 [`AGENTS.md`](AGENTS.md)。

## 为什么要把“性能优化”和“安全加固”绑在一起考？

在真实大型后端工程里，**极限性能（Turbo）**与**铜墙铁壁的安全（Shield）**天然互为紧箍咒：

| 常见偷懒套路 | 在 `xiaonuo-v3.0` 中的下场 |
| --- | --- |
| **无脑把整张表全量驻留内存或单篇修改重建整套索引** | `A1/A2/C3` 穿插高频文档 `upsert`、隔离状态翻转与动态 `doc-acl` 切换，整表重建直接拉爆高权重 `P99` 尾延迟；若驻留原始大正文，`A3` 收紧至 `≤ 4.5MB` 的常驻堆内存探针直接扣光预算分！ |
| **只更新单篇倒排，漏维护跨文档内部引用反向传播** | 当某篇 `doc_` 文档被紧急隔离或退役时，引用它的其他文档 `citation_count` 与 `score` 必须同步动态剥离；漏建反向引用依赖图在 `B1` 95+ 项跨模块守恒对账中直接失真触发 `准确率^5` 封顶！ |
| **用全局大锁逃避并发，或跨模块持锁未守全局偏序** | 全局大锁在 `A2` 跨租户并发压测中直接触发串行退化惩罚；而在 `evaluate-batch`（`REJECT` 联动扣减 `REALTIME_ALERT_POOL`）与 `quotas/transfer` 28 路交叉抢扣中，若在 `BEGIN IMMEDIATE` 内逆序请求配额锁，当场触发跨层死锁超时！ |
| **缓存漏绑二级借调上游窗口自然到期或未防有向环路** | `C1` 红队构造二级转借调并在上游一级窗口自然到期（零写操作）后同参数重搜；`C3` 红队构造双向借调有向环路，未做无环定界求值的实现当场递归栈爆炸！ |
| **只修单点二阶模板，漏看跨模块引用注入、宽度放大与侧信道** | 红队从 `docs/upsert` 的 `citations` 埋入二阶 SQL 注入与跨租户 `doc_` 引用存在性探测，并在报表标题打入 `{tenant_id:0>200000}` 宽度放大载荷，精准击穿半吊子补丁！ |

## 四个维度怎么算分（满分 100）

总分 = **A 性能压榨（32）+ B 守恒与效率（10）+ C 红队安全攻防（28）+ D 优化与安全思想（30）**。

| 维度 | 满分 | 评什么（说人话） |
| --- | --- | --- |
| **A 性能压榨** | 32 | **高频混写与动态 ACL 穿插下快了多少倍、P99 稳不稳、堆内存省不省**。① **混写检索与三跳滑窗批处理两段式对数加速比（13 分）**（拐点 95× 得 8.5 分，260× 满分）；② **14 路高并发混合读写吞吐（4.5 分）、P95（3.0 分）与高权重 P99（3.5 分）尾延迟**；③ **SQL 削减 `≥99%`（3.0 分）、流式内存下降 `≥90%`（2.2 分）与常驻堆内存预算 `≤ 4.5MB`（2.8 分）**。 |
| **B 守恒与效率** | 10 | **跨模块深水契约有没有改坏、开发节奏稳不稳**。① **95+ 项跨模块全契约零失真守恒（5 分）**：错一丝一毫即触发 `准确率^5` 全局封顶；② **端到端优化耗时（5 分）**：`8` 分钟内满分，超出按 `22` 分钟温和半衰期衰减，且受 `(A + C) / 60` 与 `(C / 28)^2` 双重封顶。 |
| **C 红队安全攻防** | 28 | **能不能扛住 20 路跨链路黑客实弹轰炸**。① **一阶与双通道二阶 SQL 注入、多编码路径穿越、`.format` 反射/宽度放大、三级隔离墙、跨租户引用侧信道与二级借调上游到期/级联竞态（10 分）**；② **32 路并发穿盾、28 路跨模块调拨+风控交叉竞争死锁探测、16 路并发 Nonce 重放与四位一体强原子回滚（9 分）**；③ **多变体 ReDoS/委托有向环路炸弹、千层 JSON/膨胀树/引用洪水、通配放大与混写/动态ACL穿透洪泛护盾（9 分）**。 |
| **D 工程思想** | 30 | **16 模块架构改造是不是殿堂级极致工艺**。对照《官方 5 级平庸参照补丁样本》执行**五档精细硬封顶盲评**：5.0级平庸 `≤ 13.5`、6.5级架构硬伤 `≤ 19.0`、7.5级局部耦合/次优 `≤ 23.0`、8.5级未达极致精细度 `≤ 26.0`、9.5级殿堂零死角大师 `27.0–30.0`。 |

## 标准同仓闭环流程

```sh
# 1) [选手域] 开局创建独立沙盒并打下 t0
python tools/start_run.py --model Demo

# 2) [选手域] 在 runs/Demo/workspace/ 内重构加固、跑通公开业务冒烟、填妥 EXPLANATION.md 后冻结打包
python runs/Demo/workspace/smoke_check.py
python src/scoring/judge_pack.py --model Demo

# 3) [评委域] 仅阅读 leaderboard/blind/<pack_id>/，对照 5 级参照样本与五档封顶规则提交 D 分
python src/scoring/judge_submit.py --pack-dir leaderboard/blind/<pack_id> --case-id case-01 \
  --judge-id judge-1 --judge-model gpt-5 \
  --D1 9.4 --D2 8.8 --D3 7.2 --evidence "[C1-C5 核验与 8.5/9.5 级分水岭核查] ..." --note "最强反证：..."

# 4) [汇总出榜] 执行隔离与计时审计，复用防篡改客观分缓存（或现场拉起高压压测与红队轰炸）+ 实时合并盲评出榜
python tools/isolation_audit.py --strict
python tools/timing_audit.py runs --strict
python leaderboard/finalize.py
```
