# Shield Turbo · xiaonuo（疾风铁盾 · 性能压榨与安全加固基准）

> **一句话**：给大模型一套由 **16 个跨模块交织文件**组成的“业务逻辑 100% 正确、功能冒烟全绿，但既慢（暗藏多级算法复杂度与混合写抖动黑洞）又脆（暗藏跨模块二阶注入、反射窃密、级联委托越权、双向调拨死锁与算法复杂度炸弹）”的多租户实时风控与合规检索网关——看谁能在**正常业务与历史兼容契约分毫不差**的前提下，同时顶住**混合读写高压压测机**与**十八路深水红队轰炸机**的双重考验。

当前赛制版本为 `xiaonuo-v2.0`（十六模块深水版）；纯 Python 标准库 + 本地 SQLite 零外部依赖同仓闭环运行。最新成绩见 [`leaderboard/scores.md`](leaderboard/scores.md)，智能体进场操作请直接阅读 [`AGENTS.md`](AGENTS.md)。

## 为什么要把“性能优化”和“安全加固”绑在一起考？

在真实大型后端工程里，**极限性能（Turbo）**与**铜墙铁壁的安全（Shield）**天然互为紧箍咒：

| 常见偷懒套路 | 在 `xiaonuo-v2.0` 中的下场 |
| --- | --- |
| **无脑把整张数据库表全量读入内存永久缓存** | `A1/A2/C3` 穿插高频实时文档写入（`upsert`/`retire`），每次整表重建索引直接把 P99 尾延迟拉爆；若把原始大正文或多代副本塞满内存，`A3` 常驻堆内存预算探针直接扣光内存控制分！ |
| **为了防并发超扣，在网关入口套一把全局互斥大锁** | 虽然防住了单池抢扣，但在 `A2` 跨租户并发混合读写压测中，所有读请求被写事务串行堵死；而细粒度锁若忘记全局锁序，又会在 `C2` 24 路双向跨池配额调拨中当场触发 AB-BA 死锁超时！ |
| **缓存漏绑委托有效期、上游撤权级联或三级利益冲突墙** | `C1` 红队先在借调有效期内预热缓存，随即跨过过期时刻或撤回上游委托人自身角色并重放同参数查询，一旦读出残留高密级文档直接判定缓存毒化泄密！ |
| **只修表层查询拼接，漏看持久化二阶模板与格式化反射** | 攻击者先向报表模板表写入合法长相的配置，再在渲染阶段触发**二阶 SQL 注入**与 Python `.format()` 对象属性反射（`{env.master_pepper}`）窃取主密钥！ |
| **为了刷假高速，漏掉隐式兼容规则或近似计算** | `B1` 80+ 项全契约对账（含词距邻近度、双轨法规折叠、三跳制裁传染、滑窗精确中位数、主权央行清算豁免）一旦准确率低于 `100%`，`A` 与 `B2` 强行乘以 `准确率^5` 指数归零！ |

## 四个维度怎么算分（满分 100）

总分 = **A 性能压榨（30）+ B 守恒与效率（15）+ C 红队安全攻防（25）+ D 优化与安全思想（30）**。

| 维度 | 满分 | 评什么（说人话） |
| --- | --- | --- |
| **A 性能压榨** | 30 | **混写高压下快了多少倍、尾延迟稳不稳、内存省不省**。① **混写检索与三跳滑窗批处理两段式对数加速比（12 分）**（拐点 60× 得 9 分，180× 满分）；② **高并发混合读写吞吐（4.5 分）与 P95（3.5 分）/ P99（2.0 分）尾延迟**（严惩全局大锁退化）；③ **SQL 查询削减（3.5 分）、流式导出内存下降（2.5 分）与常驻堆内存预算 `≤ 8MB`（2.0 分）**。 |
| **B 守恒与效率** | 15 | **有没有把隐式业务改坏、干活利不利索**。① **80+ 项全契约业务零失真守恒（5 分）**：错一丝一毫即触发 `准确率^5` 全局封顶；② **端到端优化耗时（10 分）**：`6` 分钟内满分，超出按 `8` 分钟半衰期衰减，且受 `(A + C) / 55` 与 `(C / 25)^2` 双重封顶。 |
| **C 红队安全攻防** | 25 | **能不能扛住 18 路深水黑客实弹轰炸**。① **一/二阶 SQL 注入、多变体路径穿越、`.format` 反射窃密、三级利益冲突墙与借调级联撤权竞态（9 分）**；② **30 路抢配额/令牌 TOCTOU、24 路双向跨池调拨死锁探测、12 路并发 Nonce 重放与半批传染图原子回滚（8 分）**；③ **多变体/花括号大上界 ReDoS、千层 JSON/膨胀树、通配放大与混写穿透洪泛 P95 护盾（8 分）**。 |
| **D 工程思想** | 30 | **16 模块架构改造是不是外科手术级**。对照《官方 5 级平庸参照补丁样本》执行**四档硬封顶盲评**：平庸 `≤ 14.0/30`、非增量重建或调拨死锁隐患 `≤ 20.5/30`、局部耦合或边界漏防 `≤ 24.5/30`、零死角闭环大师 `25.5–30.0/30`。 |

## 标准同仓闭环流程

```sh
# 1) [选手域] 开局创建独立沙盒并打下 t0
python tools/start_run.py --model Demo

# 2) [选手域] 在 runs/Demo/workspace/ 内重构加固、跑通公开业务冒烟、填妥 EXPLANATION.md 后冻结打包
python runs/Demo/workspace/smoke_check.py
python src/scoring/judge_pack.py --model Demo

# 3) [评委域] 仅阅读 leaderboard/blind/<pack_id>/，对照 5 级参照样本与四档封顶规则提交 D 分
python src/scoring/judge_submit.py --pack-dir leaderboard/blind/<pack_id> --case-id case-01 \
  --judge-id judge-1 --judge-model gpt-5 \
  --D1 9.5 --D2 9.0 --D3 8.5 --evidence "[C1-C5 核验通过] ..." --note "最强反证：..."

# 4) [汇总出榜] 执行隔离与计时审计，复用防篡改客观分缓存（或现场拉起高压压测与红队轰炸）+ 实时合并盲评出榜
python tools/isolation_audit.py --strict
python tools/timing_audit.py runs --strict
python leaderboard/finalize.py
```
