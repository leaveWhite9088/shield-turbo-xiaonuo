# Shield Turbo · xiaonuo（疾风铁盾 · 性能压榨与安全加固基准）

> **一句话**：给大模型一套“业务逻辑 100% 正确、功能冒烟全绿，但既慢（暗藏多级复杂度与 I/O 黑洞）又脆（暗藏多级越权、并发穿盾与算法复杂度炸弹）”的多租户实时风控与合规检索网关——看谁能在**正常业务分毫不差**的前提下，同时顶住**大规模高压性能压测机**与**红队黑客实弹轰炸机**的双重考验。

当前赛制版本为 `xiaonuo-v1.0`；纯 Python 标准库 + 本地 SQLite 零外部依赖同仓闭环运行。最新成绩见 [`leaderboard/scores.md`](leaderboard/scores.md)，智能体进场操作请直接阅读 [`AGENTS.md`](AGENTS.md)。

## 为什么要把“性能优化”和“安全加固”绑在一起考？

在真实后端工程里，**极限性能（Turbo）**与**铜墙铁壁的安全（Shield）**天然互为紧箍咒：

| 常见偷懒套路 | 在本基准中的下场 |
| --- | --- |
| **为了防并发超扣，在网关入口套一把全局互斥大锁** | 虽然防住了 C2 并发抢配额，但在 A2 多线程跨租户读写混合压测中，所有读请求被写事务串行堵死，并发吞吐与尾延迟分大幅崩盘。 |
| **为了刷高检索吞吐，无脑上全局内存缓存或漏做撤权失效** | 提速看似飞快，但紧接着 C1 红队发起“跨租户/跨密级探测”与“管理员撤回授权后 1 毫秒缓存刺探”，一旦读出脏缓存直接判定泄密重扣安全分。 |
| **为了刷 0.1ms 假高速，删减计算步骤或近似返回** | B1 60+ 项高密度对账一旦准确率低于 `100%`，A 性能分与 B2 耗时分直接乘以 `准确率^4` 指数级归零。 |
| **只加表层索引、用 `.replace("../", "")` 应付安全检查** | 无法降伏 $O(N^2)$ 近似聚类去重与全量内存膨胀，且被 `....//` 路径穿越、ReDoS 正则回溯炸弹与深层膨胀规则树当场击穿；盲评对照《官方 5 级平庸参照补丁样本》锁死在 `≤ 15/30` 分。 |

## 四个维度怎么算分（满分 100）

总分 = **A 性能压榨（30）+ B 守恒与效率（15）+ C 红队安全攻防（25）+ D 优化与安全思想（30）**。

| 维度 | 满分 | 评什么（说人话） |
| --- | --- | --- |
| **A 性能压榨** | 30 | **到底快了多少倍、省了多少资源**。同机对比初始原版按对数连续插值算分：① **批量与复杂检索加速比（12 分）**（提速 30 倍以上满分，只加表层索引提速 3 倍仅得约 4 分）；② **高并发读写混合吞吐与 P95 尾延迟（10 分）**（严惩全局大锁串行退化）；③ **SQL 查询放大削减与流式内存峰值下降（8 分）**。 |
| **B 守恒与效率** | 15 | **有没有把业务改坏、干活利不利索**。① **业务输出零失真守恒（5 分）**：60+ 组复杂多租户场景与原版逐项比对，错一丝一毫即触发 `准确率^4` 全局封顶；② **端到端优化耗时（10 分）**：`8` 分钟内满分，超出按 `10` 分钟半衰期衰减，且受 `(A + C) / 55` 质量得分率封顶（杜绝交白卷秒退骗快分）。 |
| **C 红队安全攻防** | 25 | **能不能扛住黑客实弹轰炸**。① **注入、多变体路径穿越、泄密、横向/纵向越权与撤权缓存刺探（9 分）**；② **30 路屏障同步并发抢配额/核销令牌（TOCTOU）与回调重放防御（8 分）**；③ **并发投递 ReDoS 正则炸弹、千层嵌套/扇出规则树炸弹、`limit=-1` 慢查询放大炸弹时毫秒级熔断且正常租户流量 P95 零拖累（8 分）**。 |
| **D 工程思想** | 30 | **架构改造是不是外科手术级**。打包脚本自动生成脱敏 `code_changes.diff` 并附带《官方 5 级平庸参照补丁样本》，由独立评委盲评：① **算法降维与锁/缓存粒度（11 分）**、② **纵深防御体系化（10 分）**、③ **代码品味与 5 条核心声明诚实度（9 分）**。 |

## 它能测出什么、测不出什么（客观边界）

### 它测得很准的地方
1. **无提示自主病灶定位能力**：沙盒公开冒烟脚本只测小样本正常功能回归，代码注释彻底去剧透化，绝不提示哪行慢、哪行有漏洞；模型必须像真实首席工程师一样通读跨模块源码自主排查。
2. **算法与系统工程硬功底**：清晰区分“只会加单列索引和全局锁的初级修补”（客观分约 30–38/70）与“能写出倒排分桶剪枝、窗口批量预取、游标流式化、SQLite WAL 细粒度锁及纪元版本精准失效缓存的高阶架构师”（客观分 68+/70）。
3. **盲评防通胀与诚实度核验**：盲评包强制捆绑《官方 5 级平庸参照补丁样本》做硬参照，且要求评委逐条核验 `EXPLANATION.md` 中的 5 条代码声明，吹牛或停留在平庸补丁水平会被直接封顶。

### 它测不到或有局限的地方
1. **单机 SQLite 存储模型边界**：为保证零外部服务依赖与 100% 确定性复现，系统基于单机多线程 + SQLite 构建，不直接考核分布式多机 Redis/PostgreSQL 跨网络缓存一致性协议或容器编排运维。
2. **端到端耗时分受推理网速影响**：B2 统计从开局 `t0` 到打包 `t1` 的现实墙钟时间，深度长思考模型或低吞吐 API 渠道在耗时子项上会有一定折损。

## 标准同仓闭环流程

```sh
# 1) [选手域] 开局创建独立沙盒并打下 t0
python tools/start_run.py --model Demo

# 2) [选手域] 在 runs/Demo/workspace/ 内重构加固、跑通公开业务冒烟、填妥 EXPLANATION.md 后冻结打包
python runs/Demo/workspace/smoke_check.py
python src/scoring/judge_pack.py --model Demo

# 3) [评委域] 仅阅读 leaderboard/blind/<pack_id>/，对照 5 级参照样本提交或随时重评 D 分
python src/scoring/judge_submit.py --pack-dir leaderboard/blind/<pack_id> --case-id case-01 \
  --judge-id judge-1 --judge-model gpt-5 \
  --D1 9.5 --D2 9.0 --D3 8.5 --evidence "[C1-C5 核验通过] ..." --note "最强反证：..."

# 4) [汇总出榜] 执行隔离与计时审计，复用防篡改客观分缓存（或现场拉起高压压测与红队轰炸）+ 实时合并盲评出榜
python tools/isolation_audit.py --strict
python tools/timing_audit.py runs --strict
python leaderboard/finalize.py
```
