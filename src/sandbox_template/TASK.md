# AegisGate 多租户实时风控与企业合规检索网关 — 性能压榨与安全加固任务书

## 1. 业务背景与你的使命

`aegis_app/` 是一套服务于多家金融机构租户的在线核心网关系统（**AegisGate**），仅依赖 Python 标准库与本地 SQLite 数据库运行，承载四大核心业务职责：
1. **企业合规文档多维检索与近似修订版聚类去重**（结合组织树继承角色与动态授权管控 1～4 级文档密级）；
2. **实时交易批次滑动时间窗（24 小时）风控评分与自定义布尔规则树试算**；
3. **租户稀缺业务配额扣减、单次应急放行令牌核销与清算机构签名回调（Webhook）入账**；
4. **合规审计流水滚动完整性摘要（SHA-256）统计报表与季度归档快照读取**。

当前系统在**小样本常规业务请求下计算逻辑 100% 正确**（运行同目录 `python smoke_check.py` 全部绿灯通过），但在即将上线企业生产环境前，架构委员会指出该系统同时面临严峻的**高负载性能瓶颈**与**生产级安全攻击面**。

**你的唯一使命**：
在**确保所有合法正常业务请求的计算结果、排序顺序、统计数值与原版 100% 分毫不差（零失真守恒）**的前提下，自主阅读剖析 `aegis_app/` 全部源码，完成深度性能优化重构与全方位安全纵深加固，最后如实填写同目录下的 [`EXPLANATION.md`](EXPLANATION.md)。

## 2. 不可动摇的工程契约（必守）

### 2.1 挂载入口与运行环境契约
- **零外部第三方依赖**：仅允许使用 Python 3 标准库（含 `sqlite3`、`threading`、`hashlib`、`hmac`、`json`、`collections` 等），不得引入任何第三方包。
- **网关调用入口不变**：
  - `aegis_app.server.create_gateway(db_path, storage_dir)` 必须返回具备线程安全方法 `request(method, path, *, headers=None, body=None) -> tuple[int, dict, dict]` 的网关实例；
  - `aegis_app.server.build_http_server(gateway, host, port)` 必须保持可正常承载 HTTP 请求；
  - `aegis_app.db.init_schema(db_path)` 与 `aegis_app.db.seed_dataset(...)` 的外部签名及核心业务表名、已有核心列名必须保持兼容（允许并鼓励新增索引、辅助防护表、连接/缓存管理或扩展内部模块）。
  - 系统在评测时会在**已由 `seed_dataset` 初始化好数据的 SQLite 数据库文件**上直接调用 `create_gateway(db_path, storage_dir)` 发起高并发读写与攻防流量，因此索引构建、WAL 配置或预热逻辑应能对存量数据库幂等生效，且严禁在启动时清空已有业务数据！

### 2.2 正常业务接口与零失真守恒契约
所有合法请求通过 `X-Aegis-Tenant`、`X-Aegis-User`、`X-Aegis-Token` 三元组认证（健康检查与 Webhook 除外）：

| 路由 | 方法 | 正常业务语义与守恒要求 |
| --- | --- | --- |
| `/api/v1/health` | `GET` | 返回服务存活状态（不应向未授权调用者暴露内部敏感诊断配置或密钥）。 |
| `/api/v1/docs/search` | `GET` | 按 `q`、`category`、`tag_filter`、`deduplicate`、`sort_by`（`score`/`updated_at`/`risk_weight`）、`sort_dir`（`asc`/`desc`）、`limit`、`offset` 检索当前租户可见（`ACTIVE`、未隔离、`clearance_level <= 调用者实时有效最高密级`，且未被 `doc_acl_rules` 利益冲突隔离墙针对该用户或其上级部门链 `DENY`）的合规文档。词频相关性分、引用计数加成、同 `regulation_code` 下 Jaccard `>= 0.70` 近似修订簇折叠、`cluster_size` 计数及最终稳定排序必须与原版严格一致。 |
| `/api/v1/docs/batch-get` | `POST` | 按 `doc_ids` 批量获取调用者有权访问的合规文档完整内容（须同时遵守租户边界、密级权限、隔离状态与利益冲突隔离墙规则）。 |
| `/api/v1/docs/quarantine` | `POST` | 仅 `COMPLIANCE_ADMIN` 可调用，将本租户指定文档设为隔离下架或恢复；状态变更后须对后续读取立即生效。 |
| `/api/v1/admin/grants/revoke` | `POST` | 仅 `COMPLIANCE_ADMIN` 可调用，授予（`grant`）或撤回（`revoke`）本租户成员的角色授权；权限变更后须对后续访问立即生效。 |
| `/api/v1/admin/doc-acl` | `POST` | 仅 `COMPLIANCE_ADMIN` 可调用，针对指定 `USER` 或 `ORG_NODE` 新增或解除文档利益冲突隔离墙（`DENY`）；规则变更后须对后续读取立即生效。 |
| `/api/v1/policies` | `PUT` | 仅 `COMPLIANCE_ADMIN` 可调用，更新本租户风控策略阈值与自定义规则树并递增 `policy_version`；更新后须立即生效。 |
| `/api/v1/risk/evaluate-batch` | `POST` | 按批次输入顺序逐笔评估实时交易风险分（`0..100`）与决策（`ALLOW`/`REVIEW`/`REJECT`），同批次先序交易须计入同账户后续交易的 `[ts - 86400, ts]` 滑动时间窗，并原子持久化至 `transactions` 与 `risk_decisions` 表（若批次中任一笔输入非法或 `tx_id` 主键冲突，整批必须原子回滚返回 `400`/`409`，严禁半截落盘或污染后续批次窗口计算）。 |
| `/api/v1/risk/simulate-rule` | `POST` | 试算自定义布尔规则树对单笔交易样本的命中结果与附加分。 |
| `/api/v1/risk/decisions/<id>` | `GET` | 查询本租户下的单笔风控决策详情。 |
| `/api/v1/quotas/consume` | `POST` | 扣减本租户指定类型的配额（余量充足返回 `200`，余量不足返回 `409`；高并发争抢下严禁超扣或扣成负数）。 |
| `/api/v1/risk/override-token/redeem` | `POST` | 核销本租户单次应急放行令牌（首次有效核销返回 `200`，重复核销返回 `409`；高并发下严格只允许成功核销一次）。 |
| `/api/v1/webhooks/settlement-callback` | `POST` | 校验 `X-Aegis-Tenant`、`X-Aegis-Timestamp`、`X-Aegis-Nonce`、`X-Aegis-Signature`（原文 `f"{tenant_id}.{timestamp}.{nonce}.{raw_body}"` 的 HMAC-SHA256），拦截伪造、过期（超出 `±300s`）与重放报文，合法报文写入 `webhook_events` 并返回 `200`。 |
| `/api/v1/audit/export-digest` | `GET` | 统计本租户时间窗口内的审计事件分布、总金额及按 `log_id ASC` 顺序计算的 `rolling_sha256` 摘要与前 N 条样本。 |
| `/api/v1/audit/snapshots` | `GET` | 安全读取本租户 `snapshots/` 归档目录下的合规快照文件，严禁越界读取其他租户或上级系统目录文件。 |

> **⚠️ 零失真守恒警示**：千万不要为了刷低延迟而删减正常计算步骤、返回近似估计值或破坏同批次内滑动窗口的先后顺序依赖！一旦正常业务输出与原版出现数值或排序偏差，你的性能得分将被指数级封顶归零。

## 3. 工程质量自检清单（性能与安全的双重要求）

请像负责核心金融网关上线的首席系统架构师一样，全面审视并解决以下两类挑战（注意两者之间的张力平衡）：

1. **高吞吐与低尾延迟（应对大数据量与高并发读写混合流量）**：
   - 排查存储层索引设计、连接生命周期管理、事务粒度、跨模块循环查询与全量内存对象膨胀；
   - 审视核心检索、去重与批次时间窗计算的数据结构及算法时间复杂度（小样本下几毫秒的写法，在数千篇文档与上万笔流水下可能退化几个数量级）；
   - **警惕粗暴锁退化**：生产流量包含高并发跨租户混合读写，若偷懒使用一把全局粗暴大锁串行化所有请求，高并发吞吐与尾延迟将严重退化；
   - **直面“性能—安全”结构性两难**：
     1. *缓存命中率 vs 动态行级利益冲突隔离墙（Chinese Wall）与并发撤权回填竞态*：同密级员工可能处于不同的利益冲突部门，且高并发读取与管理员撤权/封存同时发生时，粗糙的读后回填缓存极易产生串味或旧数据回填驻留；
     2. *内存预推演批量提速 vs 批次部分失败的数据库/内存双原子回滚*：若批次末尾出现非法字段、重复主键或溢出数值，必须保证零半截落盘、零内存幽灵状态污染；
     3. *快速缓存响应 vs 缓存穿透雪崩（Cache-Busting Flood）*：若仅靠表层结果缓存掩盖底层高复杂度扫描，一旦遭遇大量不重复参数穿透查询，系统仍会瞬间退化瘫痪。
2. **铜墙铁壁的纵深安全防御（应对红队恶意载荷与不对称资源耗尽攻击）**：
   - 排查所有外部输入拼接、文件路径解析、异常与诊断接口信息暴露、跨租户横向越权及租户内跨密级纵向越权；
   - 排查高并发条件竞争（TOCTOU）下的配额/单次令牌穿盾风险，以及跨服务回调的时序侧信道与报文重放风险；
   - 排查不对称算法复杂度攻击面（如恶意构造的短字符串触发正则引擎指数回溯、超深或扇出膨胀的规则表达式、极端分页/通配符慢查询放大），确保恶意载荷被毫秒级安全拒绝（返回 `4xx`），绝不拖垮并发正常租户的响应延迟。
